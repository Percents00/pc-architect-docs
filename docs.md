# Требования и роадмапа

## Функциональные требования

| Код | Требование |
| --- | --- |
| FR-1 | Каталог семи категорий комплектующих, поиск и фильтрация по характеристикам |
| FR-2 | Выбор, замена и удаление компонентов; изменение количества RAM; очистка сборки и заполнение примера |
| FR-3 | Автоматическая проверка сокетов, памяти и слотов, форматов и размеров, охлаждения и мощности БП |
| FR-4 | Обновляемая оценка мощности по CPU и GPU с указанием требуемого БП и запаса |
| FR-5 | Сохранение, открытие, изменение и удаление собственных приватных сборок |
| FR-6 | Личный кабинет с данными пользователя и списком его сборок |
| FR-7 | Регистрация по имени, email, паролю и подтверждению; проверка данных и уникальности на сервере |
| FR-8 | Вход по email и паролю, восстановление сеанса, выход и серверная проверка доступа |

## Нефункциональные требования

| Код | Требование |
| --- | --- |
| NFR-1 | Локальный запуск Django и PostgreSQL по инструкции. Развёртывание — отдельный этап: Docker Compose и Nginx, Arch Linux с 8 ГБ RAM; контейнеры суммарно до 1,5 ГБ |
| NFR-2 | Серверная проверка совместимости — до 150 мс без учёта сети |
| NFR-3 | Удаление компонента через ORM сохраняет сборку, очищает слот и сбрасывает результат проверки в одной транзакции; удаление RAM обнуляет количество |
| NFR-4 | Читаемый и доступный интерфейс при ширине окна от 1280 пикселей |
| NFR-5 | Логирование запросов, ошибок, авторизации и изменений данных: время, уровень, описание, ID запроса; ротация журналов; без паролей и токенов |
| NFR-6 | HTML, CSS, JavaScript; Python 3.14, Django 5.2, PostgreSQL 18 и Django ORM. HTTP API; версии Python-зависимостей фиксируются в `backend/requirements.txt`. Серверная проверка совместимости — цель реализации |
| NFR-7 | UUID для идентификаторов; SMALLINT и ограничения значений для числовых характеристик, количества модулей и слотов. Вычисления — в более широком типе |
| NFR-8 | Пароли — хеши Django; access — короткоживущий JWT в памяти браузера; refresh — одноразовый секрет в HttpOnly cookie с хранением хеша в БД, ротацией и отзывом семейства. CSRF-защита и ограничение попыток входа |

## Бизнес-требования

- Помочь пользователю подобрать совместимые комплектующие из единого каталога.
- Сохранять конфигурации для дальнейшей работы в личном кабинете.
- Предусмотреть рекламу производителей и магазинов: явная пометка «Реклама», без влияния на проверку совместимости и без помех работе конструктора.

## Роадмапа

### ЛР1 — анализ и проектирование

- Определить назначение приложения и основные сценарии использования.
- Подготовить требования и концептуальную схему данных.
- Выделить репозитории фронтенда, бэкенда и проектной документации.

### ЛР2 — прототип интерфейса и подготовка архитектуры

- Создать конструктор на HTML, CSS и JavaScript с локальным каталогом комплектующих.
- Реализовать выбор и удаление компонентов, базовую проверку совместимости и заполнение примера.
- Согласовать стек, схему БД, основные маршруты и форматы API.

### ЛР3 — локальная версия с БД и личным кабинетом

- Подключить PostgreSQL через Django ORM, подготовить модели, миграции и начальное заполнение каталога.
- Подключить интерфейс к API категорий и комплектующих.
- Реализовать регистрацию, вход, восстановление сеанса и выход с access/refresh-токенами, ротацией, отзывом и CSRF-защитой.
- Добавить личный кабинет с профилем и приватными сборками: сохранением, открытием, изменением и удалением.
- Проверять права доступа: пользователь работает только со своими сборками.
- Обеспечить базовую проверку совместимости в браузере: сокеты, тип памяти, число модулей RAM и мощность БП.
- Проверить основные сценарии, авторизацию и изоляцию данных; подготовить инструкцию локального запуска.

Результат к ЛР3 — работающее локально приложение с подключённой БД, авторизацией и личными сборками, без развёртывания на внешнем сервере. Публичные сборки, общая лента, ссылки для обмена и комментарии в этот этап не входят.

### После ЛР3 — развитие и развёртывание

1. Перенести проверку совместимости на сервер; добавить размеры, форматы и охлаждение, расширить фильтры каталога.
2. Реализовать логирование с ротацией и показ рекламы из БД.
3. Проверить основные сценарии работы, производительность и резервное копирование.
4. Подготовить Docker Compose, Nginx и HTTPS, выполнить развёртывание.
5. При возвращении публичных функций в объём работ добавить публикацию, ленту, ссылки и комментарии.
