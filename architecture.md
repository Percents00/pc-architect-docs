# Архитектура, БД и API

## Репозитории

`pc-architect-frontend` содержит интерфейс приложения; `pc-architect-backend` — Django, модели, миграции и начальный каталог; `pc-architect-docs` — документацию. Локально они размещаются в соседних папках `frontend`, `backend`, `documentation`.

Django читает интерфейс из `FRONTEND_DIR`, по умолчанию из соседней папки `frontend`. API и начальные данные бэкенда не зависят от фронтенда или документации. Совместный запуск сохраняет один адрес страницы и API, поэтому механизм cookie и CSRF не меняется.

## Устройство приложения

Браузер → Django HTTP API → Django ORM → PostgreSQL.

- `app.js` загружает каталог, управляет конструктором и личными сборками.
- `auth.js` обрабатывает формы входа и регистрации, обновляет сеанс.
- `compatibility.js` проверяет совместимость в браузере.
- `core/views.py` обслуживает каталог, `auth_views.py` — авторизацию, `build_views.py` — личные сборки.
- `core/models.py` описывает таблицы; `core/migrations/` создаёт и изменяет их.

Данные каталога читаются из БД. `backend/core/fixtures/components.json` используется командой `seed_catalog`. Пользовательские сборки доступны через личный кабинет. Несохранённый состав находится в памяти страницы, сохранённые сборки — в PostgreSQL.

## База данных

| Модель / таблица | Назначение и основные поля |
| --- | --- |
| `User` / `users` | Пользователь: UUID, username, email, хеш пароля, признаки активности и администратора |
| `RefreshToken` / `refresh_tokens` | Пользователь, family_id, token_hash, created_at, expires_at, used_at, revoked_at |
| `LoginThrottle` / `login_throttle` | Хеш ключа ограничения, число неудачных входов и начало окна |
| `ComponentCategory` / `component_categories` | Название, код категории, иконка, порядок отображения |
| `Processor` / `processors` | Сокет, TDP, поддерживаемый тип памяти |
| `Motherboard` / `motherboards` | Сокет, формат, тип памяти, число слотов RAM |
| `GraphicsCard` / `graphics_cards` | Длина, TDP, рекомендуемая мощность БП |
| `RamModule` / `ram_modules` | Тип, объём и высота модуля |
| `PowerSupply` / `power_supplies` | Мощность, формат, сертификат эффективности |
| `PcCase` / `pc_cases` | Поддерживаемые форматы плат, предельные длина GPU и высота кулера |
| `Cooler` / `coolers` | Теплоотвод, высота, поддерживаемые сокеты |
| `PcBuild` / `pc_builds` | Владелец, название, описание, ссылки на компоненты, количество RAM, даты и поля результата проверки |
| `BuildComment` / `build_comments` | Сборка, автор, текст и дата комментария |
| `Advertisement` / `advertisements` | Рекламодатель, заголовок, изображение, ссылка, площадка и период показа |

`User` наследует `AbstractUser`. У компонентов общие поля: UUID, category_id, name, source_url, spec_note. Абстрактная модель `Component` не создаёт отдельной таблицы. Поддерживаемые сокеты и форматы хранятся массивами строк. Даты — с часовым поясом, работа приложения — в UTC. Числовые характеристики используют SMALLINT с ограничениями.

Пользователь связан со своими сборками и токенами. Сборка ссылается на компоненты, компонент — на категорию. Имя пользователя и email уникальны без учёта регистра.

При удалении компонента через ORM `signals.py` очищает слот и сбрасывает результат проверки; для RAM обнуляется количество. Сборка сохраняется. Категорию с компонентами удалить нельзя; удаление сборки удаляет её комментарии. Прямые SQL-запросы не вызывают обработчики Django.

`share_slug` и `is_public` присутствуют в модели сборки, но API публикации нет; сохранение через сайт создаёт приватные сборки. Таблицы комментариев и рекламы подготовлены для следующих этапов.

## Авторизация и токены

Регистрация принимает `username`, `email`, `password`, `password_confirm`. Имя — 3–40 латинских букв, цифр или `_`; email — до 254 символов; пароль — 12–128 с проверками Django. Имя и email очищаются от пробелов по краям и приводятся к нижнему регистру. Пароль не обрезается, подтверждение не хранится. После регистрации выполняется отдельный вход.

- Access: JWT с подписью HS256, срок 15 минут; только в памяти JS, передаётся в `Authorization: Bearer …`. Сервер проверяет подпись, срок, issuer, audience, тип токена, пользователя и активность семейства.
- Refresh: случайный секрет 256 бит. Браузер хранит его в cookie `HttpOnly`, `SameSite=Strict`, `Path=/api/auth/`, без Domain. В БД хранится SHA-256 хеш. При HTTPS используется Secure; локальный HTTP разрешён в режиме разработки.
- Срок семейства — 30 суток от входа. Обновление помечает токен использованным и создаёт новый с теми же family_id и сроком окончания. Операция выполняется в транзакции с блокировкой строк; использованные записи сохраняются для обнаружения повторов.
- Повторное использование refresh отзывает семейство. Выход также отзывает семейство и удаляет cookie; если cookie отсутствует, сервер может определить сеанс по access. Проверка семейства при защищённых запросах блокирует выданные access после отзыва.
- Клиент объединяет параллельные обновления. Web Locks сериализует операции между вкладками; BroadcastChannel передаёт только уведомления о входе и выходе. Без Web Locks конкурирующее использование refresh в разных вкладках может завершить сеанс.
- Изменяющие запросы требуют CSRF cookie и `X-CSRFToken`. После перезагрузки вход восстанавливается через refresh. Токены не записываются в localStorage, sessionStorage или URL. Ответы авторизации и личных данных имеют `Cache-Control: no-store`.
- Лимит входа — 5 неудачных попыток на email и 20 на IP за 15 минут; превышение даёт 429. Ключи ограничений хранятся в `login_throttle` как хеши.

Ключ подписи берётся из `DJANGO_SECRET_KEY`. Для локальной разработки автоматически создаётся `backend/.django-secret-key`, исключённый из Git. Без DEBUG переменная обязательна. Пароли хранятся штатными средствами Django; пароли и токены не должны попадать в журналы.

## API

| Метод и путь | Результат |
| --- | --- |
| `GET /api/categories/` | `{items}` — категории |
| `GET /api/components/` | `{items, total, page, page_size}` — комплектующие |
| `GET /api/components/{id}/` | Характеристики компонента |
| `GET /api/auth/csrf/` | 204 и CSRF cookie |
| `POST /api/auth/register/` | 201 `{user}` |
| `POST /api/auth/login/` | Access, данные пользователя и refresh cookie |
| `POST /api/auth/refresh/` | Новый access и замена refresh cookie |
| `POST /api/auth/logout/` | 204, отзыв сеанса и удаление cookie |
| `GET /api/auth/me/` | Данные пользователя по access |
| `GET /api/builds/` | Список собственных сборок |
| `POST /api/builds/` | Создание сборки, 201 |
| `GET/PATCH/DELETE /api/builds/{id}/` | Чтение, изменение и удаление своей сборки |

Тела — JSON, UUID — строки. Личные сборки и `auth/me` требуют access. Изменения дополнительно требуют CSRF. Чужая сборка возвращает 404.

Каталог принимает `category`, `q`, `page`, `page_size`. Категории: `cpu`, `motherboard`, `gpu`, `ram`, `psu`, `case`, `cooler`. Размер страницы — 1–100, по умолчанию 20; список личных сборок поддерживает `page` и `page_size`. Поиск и выбор категории в интерфейсе выполняются по загруженному каталогу.

Вход принимает `{email, password}`. Ответ входа и обновления: `{access_token, token_type: "Bearer", expires_in: 900, user: {id, username, email, is_staff}}`. Refresh не возвращается в JSON.

Создание сборки принимает `title`, необязательное `description`, поля `cpu_id`, `motherboard_id`, `gpu_id`, `ram_id`, `psu_id`, `case_id`, `cooler_id` и `ram_count`. PATCH принимает часть этих полей. Название — непустая строка до 120 символов, описание — до 2000. Пустой слот — null; без RAM количество равно 0, с RAM — 1–16. Владелец назначается сервером, передавать `is_public` и результат проверки нельзя.

Ответ сборки: `{id, title, description, selection, created_at, updated_at}`. `selection` содержит ID компонентов и количество RAM. Сервер проверяет существование компонентов и их категории. Неполные и конфликтные сборки разрешено сохранять.

Ошибки: `{code, message, errors?}`. Основные коды HTTP: 400 — неверный JSON, 401 — ошибка входа или сеанса, 403 — CSRF, 404 — объект не найден или недоступен, 409 — имя/email заняты, 422 — неверные поля, 429 — лимит попыток, 503 — недоступна БД.

## Проверка совместимости

Браузер проверяет сокеты CPU и платы, поддержку типа RAM процессором и платой, число модулей и мощность БП. Оценка мощности: `CPU.base_tdp + GPU.tdp`. Требуемый БП: большее из суммы с запасом 20% и рекомендации видеокарты. Остальные узлы и пиковые нагрузки в расчёт не входят.

Результат содержит статус, предупреждения, незаполненные слоты и показатели мощности. Перенос проверки на сервер, размеры, форматы и охлаждение включены в [роадмапу](docs.md#роадмапа).
